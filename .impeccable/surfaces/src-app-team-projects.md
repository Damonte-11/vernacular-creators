Mode: operate

THESIS: A Chorus project page answers one question before anything else: are we on track for the views guarantee? Everything else (who is late, which links are missing, how engagement is holding up) sits one glance below, and adding post links is a paste, not a form.

OWN-WORLD: The existing Vernacular Creators world, unchanged: Alabaster canvas, white cards, Eerie Black primary actions, Vernacular Orange only for highlights, Outfit, green / golden yellow / red only for status and always with a word. No new palette, type or controls.

STORY: Campaign manager opens the project between meetings, reads the guarantee line (on track / behind by X / met), sees the short "needs attention" list (late creators, posts with no numbers yet), pastes the links creators sent on WhatsApp, and moves on.

FIRST VIEWPORT: App shell sidebar; project header (client, Chorus type, window, day N of M); the guarantee panel with the pace bar and a one-line verdict, then a single quiet row of the five reported numbers (views, engagements, ER by views, posts, creators); the needs-attention list beside it on desktop, under it on phone; the paste-links bar; then the work area.

FORM: Seed roll dealt lanes (lead), the window calendar and the post grid. All three are built behind a "Layout" switch in the Design preview banner so the team can lock one by using them: Lanes = creators moving Waiting / Late / Posted / Day-7 numbers in; Calendar = creators against the days of the window with due dates and posts; Posts = every post with its numbers, problems first. No money, rates or CPM anywhere.

MEMORABLE MOMENT (signature move): the guarantee pace bar: orange fill for views so far, a black notch for where the campaign should be today, the guarantee as the end of the bar, and the verdict written in words next to it.
